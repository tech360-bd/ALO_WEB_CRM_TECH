## Concrete patches

- Revalidate current employee status for every request through `authenticateRequest`, including CRM, communication and AI paths.
- Reject student/partner identities on `/api/employee/*`; apply existing origin protection to its mutations.
- Only exact Super Admin retains the wrapper permission bypass. Admin must satisfy configured checks.
- Expired/revoked/missing/foreign Acting-As sessions return 403 instead of silently falling back to Super Admin. The exact stop POST can clear stale cookies.
- Explicit disabled/approval-required feature rules take precedence over temporary/package/self-field grants.
- Add missing route wrappers around eleven existing employee components; sidebar now navigates to real routes.
- Keep activation outside the authenticated employee shell.
- Repair feature-rule persistence to actual Prisma columns. Validate requests, require a real employee target, restrict changes to non-acting Super Admin, audit in the same transaction, and use safe errors.
- Replace the feature tab’s API instructions and nonexistent fields with an actual create/edit form. Existing operational modules remain in place.

## Outstanding acceptance blockers

1. Missing routes: eleven employee navigation routes were added; all sixteen requested dashboard routes exist. A route inventory alone does not prove child workflows.
2. Missing UI: full profile fields, role-aware menu gating, approvals, exit/reassignment and every requested role widget still need authenticated UI acceptance. Existing widgets must be audited individually.
3. Missing API: all requested logical employee API groups have source paths; profile uses PUT rather than requested PATCH. API completeness/security must be checked per handler.
4. Missing database: no local MySQL connection was provided. Actual foreign keys, applied migrations, encrypted sensitive values, version invariants and transactional behavior are unverified.
5. Missing RBAC: legacy helpers remain alongside the central engine; `object-scope.ts` still treats ADMIN/CHAIRMAN as master and `access-check-engine.ts` accepts caller role arrays in some helpers. Those paths require consolidation before global least-privilege acceptance.
6. Missing audit: central audit helper can swallow errors outside transactions; end-to-end audit coverage across every sensitive controller is unproven.
7. Broken workflow: known sidebar navigation and feature-rule writes patched here. End-to-end activation, deactivation/reassignment, Acting-As, salary, payments, provider delivery and payroll approvals remain unverified.
8. Failed test: see validation results below. Skipped database tests are not passes.
9. Build error: see validation results below; Node 22 must be used.
10. External dependencies: isolated MySQL, protected storage, SMTP, officially connected messaging/social providers, MFA configuration, signature provider if needed, free/local AI inference, production runtime/deployment evidence.

## Additional defects patched during deeper inspection

- Removed fictional salary, leave, performance and report fallback records. These views now consume the existing API envelopes, show empty/error states, and do not announce failed leave submissions as successful.
- Salary endpoint now resolves the authenticated Employee, selects only approved/paid payroll, excludes calculation/private-field arrays, logs reads/downloads, and serves an escaped branded HTML payslip attachment. This is an HTML payslip, not a fabricated PDF.
- Both existing payroll read surfaces now restrict ordinary employees to approved/paid records and projected final salary fields. Broad salary visibility requires exact Super Admin or `employee.fields.salary.view_all`.
- Appointment list/details/create/edit/archive now check canonical student assignment and the central `employee.appointments` action permission. No synthetic general student is created. Calendar sends an explicit date/time and requires a real assigned student ID. Cross-branch/country manager delegation remains to be implemented through the full central scope model.
- Appointment cancellation retains history and uses a transactional audit. Employee task deletion now archives rather than destroys the row; manager titles no longer bypass task ownership on edit.
- Leave approval no longer exempts Super Admin from self-approval prevention; invalid review decisions are rejected.
