## Database and APIs

No database tables, columns, migrations, roles or dependencies were added. Reused `PermissionPackage`, `EmployeePermissionPackageAssignment`, `MarketingTemplate`, `PortalAuditLog`, `Employee`, `EmployeeHR`, `FeatureAccessRule` and current account/session models. Existing permission-package response keys `employeePackages` and `partnerPackages` remain available. The new package UI is restricted to master authority; scoped HR delegation is not introduced by this patch.

Package POST updates when `id` is supplied and creates otherwise. PATCH assigns or revokes. Every mutation requires a reason, an authenticated non-acting Super Admin and the existing employee-origin check. Revocation retains history. Approval-gated permission entries do not grant execution authority by themselves; this patch does not implement automatic approval consumption.

Diagram drafts have no publication action and no delete endpoint. Only the author can list or overwrite their drafts, including when a broader permission exists. Updating requires `expectedUpdatedAt`; stale updates return 409. Content is validated JSON, not raw HTML, scripts or arbitrary SVG.
